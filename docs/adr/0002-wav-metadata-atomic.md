# ADR 0002：WAV 元数据外科写入与原子替换

- 状态：已采用
- 日期：2026-11-10

## 背景

BWF `bext` 与 iXML 是音效库的权威元数据；一次错误写入可能破坏素材，且库文件往往很大，整段复制代价高。

## 决定

- 只重建 `bext` 与 `iXML` 两个 chunk，其余 chunk 连头带数据逐字节复制，奇数长度补位保留。
- 无 `bext` 时插在 `fmt ` 之后；无 iXML 时追加到末尾；重算 RIFF 长度。
- 写入同目录临时文件，`fsync` 后回读关键字段，再 `os.replace` 原子替换；任一步失败保留原文件。
- `RF64`、非 RIFF/WAVE、截断 chunk 拒绝写元数据；改名仍可执行并提示。
- 撤销 journal 保存原始 `bext`/`iXML` chunk 的 base64，而不是复制整段音频。

## 后果

- 测试可用合成 WAV 证明往返 byte 一致。
- iXML 采用外科替换以保留未知标签；写后解析失败不落盘。
- `bext.description` 为定长字段，英文超长时只写 iXML，不截断。
